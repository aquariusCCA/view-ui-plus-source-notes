# AI 筆記優化：工作流程提示詞

## 使用定位

用來定義「從原始筆記到教材型筆記」的完整生成流程。

規則來源請以 `17-prompts/system/ai-note-optimizer-system.md` 為準，輸出樣式請以 `17-prompts/formats/note-output-formats.md` 為準。

---

## Workflow Prompt

請依照以下流程處理使用者提供的原始筆記。

---

## 1. 先判斷筆記類型

在正式改寫前，先判斷這份原始筆記比較接近哪一種類型：

| 類型 | 判斷依據 | 優化重點 |
| --- | --- | --- |
| 技術概念筆記 | 主要在解釋觀念、名詞、原理 | 補背景、補原因、補概念關係 |
| 原始碼閱讀筆記 | 有檔案路徑、方法、類別、模組、流程 | 補模組角色、入口、流程、閱讀路線 |
| API / 設定筆記 | 有 API、參數、設定檔、指令 | 補使用情境、欄位說明、注意事項 |
| 實作教學筆記 | 有步驟、程式碼、操作流程 | 補前置知識、步驟目的、錯誤排查 |
| 架構分析筆記 | 有模組、分層、資料流、依賴關係 | 補整體圖像、責任分工、設計取捨 |

如果一份筆記同時包含多種類型，請以主要用途作為主軸，其他類型作為補充小節處理。

---

## 2. 先分析原始筆記目前的問題

正式改寫前，請先簡短分析原始筆記目前的問題。分析應聚焦在「如何讓它更適合長期學習」，不要只做表面評論。

請至少檢查以下方向：

1. 哪些地方太像速查表，只列結論但缺少解釋。
2. 哪些地方缺少背景說明，導致初學者不容易理解。
3. 哪些地方需要補成教學流程。
4. 哪些地方適合用表格重整。
5. 哪些地方應該拆成後續獨立筆記。
6. 哪些內容資訊不足，必須標註「此處需要後續補充」。

---

## 3. 抽取原始筆記的核心資訊

改寫前，請先在內部完成以下整理：

1. 找出原始筆記的主題。
2. 找出原始筆記中不可遺失的核心結論。
3. 找出重要名詞、API、檔案路徑、類別、方法、設定值與流程。
4. 找出筆記中已經明確說明的內容。
5. 找出筆記中沒有說明清楚、但需要補強的內容。
6. 找出不能任意推測的內容。

改寫時要優先保留已知資訊，對不足處加上合理說明或不確定性標註。

---

## 4. 決定章節主軸

請依照筆記類型決定主軸。

如果是「技術概念筆記」，主軸通常是：

1. 背景與問題。
2. 核心概念。
3. 工作流程或使用場景。
4. 常見誤解。
5. 實務應用與複習。

如果是「原始碼閱讀筆記」，主軸通常是：

1. 專案或模組在系統中的位置。
2. 入口檔、核心檔案與支撐檔案。
3. 呼叫流程或資料流。
4. 重要 API、型別、方法與模組責任。
5. 初次閱讀路線與深入閱讀路線。

如果是「API / 設定筆記」，主軸通常是：

1. API 或設定解決什麼問題。
2. 參數、欄位與設定項目。
3. 使用情境。
4. 注意事項與常見錯誤。
5. 範例與查表。

---

## 5. 依固定格式生成教材型筆記

請依照 `17-prompts/formats/note-output-formats.md` 提供的「教書型筆記格式」輸出完整筆記。原則上使用 0 到 10 的章節架構；如果原始資料不足，可以合併部分小節，但不要省略「問題分析」、「本章定位」、「總結」與「自我檢查問題」。

即使使用固定格式，也不得將內容壓縮成摘要、速查表或單純條列清單。固定格式只用來規範章節順序與輸出外觀，不代表可以省略教學說明。每個核心章節都應包含段落式解釋，必要時再搭配表格、範例與條列整理。

每個核心小節盡量包含以下角度：

1. 這是什麼。
2. 為什麼需要它。
3. 它負責什麼。
4. 它和其他部分有什麼關係。
5. 閱讀或使用時要注意什麼。

表格與條列只能作為輔助整理，不能取代段落式教學說明。

---

## 6. 補表格、範例與閱讀路線

當原始筆記包含多個檔案、API、模組、設定、流程或概念時，請主動使用表格整理。

如果適合，請補上簡短範例或情境說明，例如：

- 使用者怎麼使用這個 API。
- 原始碼中哪裡負責處理。
- 一個請求或流程大概怎麼走。
- 初學者應該怎麼閱讀。

範例要支援理解，不要過度展開到偏離主題。

---

## 7. 加入複習與延伸設計

在筆記末尾，請加入：

1. 本章總結。
2. 5 到 10 題自我檢查問題。
3. 後續延伸方向。

自我檢查問題應包含概念理解題、流程理解題、原始碼閱讀題、比較題或實務應用題。後續延伸方向應指出這份筆記之後可以拆成哪些更深入的主題。

---

## 8. 最後做品質檢查

完成後請檢查：

1. 是否有清楚的主標題。
2. 是否使用 Markdown。
3. 標題層級是否合理。
4. 程式碼、檔案路徑、API 名稱是否使用反引號。
5. 表格是否清楚。
6. 是否避免過度零散的 bullet points。
7. 是否有標註資訊不足處。
8. 是否沒有編造未提供的技術細節。
