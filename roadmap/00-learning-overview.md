# Learning Overview

本筆記整理 `View UI Plus` 源碼學習的整體目標、主線、副線與取捨。

## 一、學習目標

這個學習工作區的目的不是把筆記寫得漂亮，而是透過源碼閱讀、元件仿寫、重構與企業級二次封裝，真正理解一套 Vue 元件庫如何被設計、實作與維護。

目標能力包括：

- 看懂 Vue 元件庫源碼
- 仿寫基礎元件
- 理解 props、emits、slots、v-model 設計
- 理解樣式 class 與狀態樣式
- 理解元件之間的共用邏輯
- 理解插件安裝、公開 API 與型別設計
- 理解建置、打包與發布流程
- 最後能做出接近公司業務場景的二次封裝元件

## 二、學習主線：元件仿寫

目前主線是：

```text
View UI Plus 原始碼
  ↓
單一元件源碼閱讀
  ↓
簡化版元件仿寫
  ↓
累積一批元件
  ↓
抽取共用邏輯
  ↓
重構練習
  ↓
企業級二次封裝
```

主線的核心原因是：

```text
先做出來，才知道自己是否真的理解。
```

如果只看源碼與整理筆記，很容易以為自己懂了，但實際寫元件時會發現 props、事件、slot、狀態、樣式與互動細節其實很多。

## 三、學習副線：元件庫工程化主題

除了元件本身，也要逐步理解元件庫背後的工程化系統。

副線包括：

- 樣式系統
- 指令系統
- 插件系統
- 公開 API 與型別系統
- 建置與發布流程
- 文件與示例系統
- 測試系統

這些主題不一定一開始深入，但要放進 roadmap，避免整個學習計畫只剩「元件列表」。

## 四、目前階段重點

目前重點是：

```text
先完成一批基礎元件仿寫。
```

建議先完成：

- Button
- Icon
- Tag
- Alert
- Badge
- Input
- Radio
- Checkbox
- Switch
- Select

完成這批後，再回頭思考：

- 哪些 props 設計重複？
- 哪些 class 組裝邏輯重複？
- 哪些狀態邏輯重複？
- 哪些地方值得抽 composable？
- 哪些設計可以用到公司業務元件封裝？

## 五、學習取捨

### 現在優先

- 元件仿寫
- 元件基本 API
- 狀態與互動
- 樣式 class 規則
- 可執行 demo
- 可回查的源碼筆記

### 之後再深入

- 完整建置流程
- 完整發布流程
- 完整主題系統
- 完整型別宣告輸出
- 大型複雜元件內部設計

## 六、判斷是否學懂

每個主題可以用三個問題檢查：

```text
1. 我能不能說明它解決什麼問題？
2. 我能不能指出它在源碼中的位置？
3. 我能不能做出簡化版或整理出可復用的設計想法？
```

如果不能，代表目前只是看過，還沒有真正吸收。
