# 筆記包資料流與更新判斷規則

這份文件定義 View UI Plus Learning Notes 的資料流、目錄責任、正式筆記生成規則，以及既有內容更新時的影響範圍判斷方式。

它是整份筆記包的主規格；README 只保留摘要與導覽。

本文件負責：

- 判斷改動發生在哪一層。
- 判斷最新正確來源在哪裡。
- 判斷哪些上游或下游需要檢查。
- 列出候選重生成或候選同步範圍。
- 提出 `00-roadmap/progress-tracker.md` 的狀態建議。

本文件不負責：

- 直接改寫筆記。
- 直接產生 atomic 或正式筆記。
- 直接產生仿寫、企業封裝或複習材料。
- 直接同步 `00-roadmap/progress-tracker.md`。

也就是說，本文件是判斷規則，不是執行授權。

---

## 核心資料流

View UI Plus Learning Notes 的內容依賴關係如下：

```text
01-origin/
  - source/
  - docs/
  - assets/
  ↓
<章節>/origin/
  ↓
資料整理
  - 資產路徑標準化
  - alt / 連結文字整理
  - origin 內容整理與切分準備
  ↓
<章節>/atomic/
  ↓
atomic review
  ↓
<章節>/*.md 正式筆記
  ↓
notes content review
  ↓
20-imitation/
21-enterprise-wrappers/
22-review-and-practice/
```

這張圖表示內容依賴順序，不表示每次更新都要全流程重跑。

核心原則：

```text
上游變動，不代表全部重跑；
但下游未檢查，也不能假設仍是最新。
```

## 建議章節結構

對於主題章節，建議使用以下結構；資產目錄只在有本地資產時按需建立：

```text
<章節>/
    origin/
        assets/          # 有本地資產時才建立
            images/      # 按實際資產類型建立
            pdfs/
            excels/
            word/
            files/
        *.md
    atomic/
    *.md                 # 正式筆記
```

`01-origin/` 是全域來源與版本基準；`<章節>/origin/` 是該章節的來源整理區。兩者都可以作為內容依據，但都不直接等同正式教學筆記。

---

## 目錄責任

| 目錄 | 作用 | 規則 |
| --- | --- | --- |
| `01-origin/` | 全域來源與版本基準 | 保存 View UI Plus 原始碼、官方文件、截圖、資產與來源紀錄。作為源碼追蹤與章節整理的最上游依據。 |
| `<章節>/origin/` | 章節原始資料區 | 保存可追溯來源、觀察、摘錄與初步整理。可以修正明顯格式問題，但不直接覆蓋成正式筆記。 |
| `<章節>/origin/assets/` | 章節資產根目錄 | 只有在章節有本地資產時才建立；沒有本地資產時可省略。 |
| `<章節>/origin/assets/images/` | 圖片資產 | 存放截圖、圖解、流程圖、元件效果圖。Markdown 需提供可理解的 alt 文字。 |
| `<章節>/origin/assets/pdfs/` | PDF 資產 | 存放 PDF 文件或外部文件快照。引用時需說明文件用途。 |
| `<章節>/origin/assets/excels/` | 試算表資產 | 存放 Excel 或 CSV 類表格資料。引用時需說明資料欄位或分析目的。 |
| `<章節>/origin/assets/word/` | Word 類文件 | 存放 Word、ODT、RTF 類材料。 |
| `<章節>/origin/assets/files/` | 其他資產 | 存放無法歸到前面類別的輔助檔案。 |
| `<章節>/atomic/` | 原子化資料區 | 根據來源重新切分、合併與修正主題邊界，作為正式筆記候選稿。 |
| `<章節>/*.md` | 正式筆記區 | 根據通過 review 的 atomic 內容生成教書型正式筆記，是仿寫、企業封裝與複習材料的基準。 |
| `20-imitation/` | 仿寫練習 | 只能根據已審查的正式筆記設計實作任務，不直接依賴未審查的 origin 或 atomic。 |
| `21-enterprise-wrappers/` | 企業封裝練習 | 只能根據正式筆記延伸企業後台封裝場景，不自行新增正式筆記未建立的核心知識。 |
| `22-review-and-practice/` | 複習與練習材料 | 只能根據正式筆記產生題目、卡片、面試題、源碼追蹤與重構練習。 |
| `99-prompts/` | AI 協作規則 | 管理提示詞、流程、格式與驗收標準，不作為 View UI Plus 知識內容本身。 |

## 內容規則

- `01-origin/` 與 `<章節>/origin/` 要保留來源感：盡量保留原始脈絡、來源路徑、相關程式碼位置與尚未整理的觀察。
- `<章節>/atomic/` 要解決主題邊界：每篇只處理一個清楚問題，不把多個主題硬塞在一起。
- 正式筆記要建立教學主線：用問題意識串起源碼、設計原因、實作流程與可遷移的設計原則。
- 正式筆記不能只像整理稿：每個關鍵結論都應該能回到原始碼、型別檔、範例或明確推論。
- 下游材料只根據正式筆記生成，不直接依賴未審查的 origin 或 atomic。
- 下游材料不能自行新增核心知識；若需要新增觀念，應先回補正式筆記並完成內容檢查。

## 更新判斷流程

每次更新、整理、檢查或候選重生成前，先回答 5 個問題：

```text
1. 改動發生在哪一層？
2. 改動類型是什麼？
3. 最新正確來源在哪裡？
4. 哪些上游或下游需要檢查？
5. progress-tracker.md 應如何建議標記？
```

判斷方向：

```text
改 01-origin/ 或 <章節>/origin/
  → 檢查 atomic / 正式筆記是否缺漏或過期

改 <章節>/atomic/
  → 檢查正式筆記是否缺漏或過期

改 <章節>/*.md 正式筆記
  → 檢查 20-imitation / 21-enterprise-wrappers / 22-review-and-practice 是否過期

改下游材料
  → 先判斷問題是否應回補正式筆記
```

## 改動類型與影響範圍

| 改動位置 | 小型文字修正 | 技術概念改動 | 結構改動 | 範例改動 | 資產 / 標題改動 |
| --- | --- | --- | --- | --- | --- |
| `01-origin/` 或 `<章節>/origin/` | 檢查 atomic / 正式筆記是否也有同錯誤 | 候選：atomic、atomic review、正式筆記、notes content review；再檢查下游 | 候選：atomic、正式筆記；再檢查下游是否依賴舊結構 | 判斷是否需要進入正式筆記 | 檢查所有引用路徑 |
| `<章節>/atomic/` | 檢查正式筆記 | 候選：正式筆記、notes content review；再檢查下游 | 候選：正式筆記與下游結構檢查 | 判斷正式筆記是否受影響 | 檢查正式筆記與下游引用 |
| `<章節>/*.md` 正式筆記 | 通常只檢查下游是否受影響 | 候選：notes content review；檢查下游 | 候選：notes content review；檢查下游是否依賴舊標題、舊順序或舊 anchor | 候選：下游練習、仿寫或複習同步 | 標題改動必查 anchor、索引與連結 |
| `20-imitation/` | 可列為直接修正候選 | 先查正式筆記是否已教 | 視正式筆記結構判斷 | 可直接修正，但不得超出正式筆記 | 檢查來源連結與引用路徑 |
| `21-enterprise-wrappers/` | 可列為直接修正候選 | 先查正式筆記是否已教 | 視正式筆記結構判斷 | 可直接修正，但不得超出正式筆記 | 檢查來源連結與引用路徑 |
| `22-review-and-practice/` | 可列為直接修正候選 | 先查正式筆記與答案來源 | 視正式筆記結構判斷 | 檢查題目、答案、卡片與來源是否一致 | 檢查來源連結、圖片與附件 |

只有符合以下條件時，才把某層列為候選重生成或候選同步範圍：

- 該層依賴的上游內容已變動。
- 該層可能引用舊標題、舊 anchor、舊範例、舊圖片或舊說法。
- 該層可能缺少正式筆記新增的內容。
- 該層可能包含正式筆記已修正的舊錯誤。
- 該層的題目、答案、展示或索引可能與正式筆記不一致。

若只是小型文字修正，且不影響標題、anchor、關鍵字、範例、資產或正式概念，通常不需要列出大範圍候選重生成。

## 檢查、候選重生成與實際執行

回答更新影響範圍時，必須區分三件事：

| 類型 | 意思 | 是否由本文件執行 |
| --- | --- | --- |
| 需要檢查 | 需要確認內容是否過期、缺漏或引用錯誤 | 否 |
| 候選重生成 / 候選同步 | 後續若授權，可能需要由其他流程處理 | 否 |
| 實際重生成 / 實際同步 | 真的改檔、產出檔案或更新狀態表 | 否 |

因此，判斷結果應使用：

```text
需要檢查
候選重生成
候選同步
建議標記
```

避免在判斷型任務中寫成：

```text
我會重生成
我會同步狀態
已更新下游
已修改 progress-tracker.md
```

除非使用者已另行明確要求執行，否則本文件只輸出判斷結果。

## 不要在下游修正上游錯誤

如果錯誤來源在正式筆記，不要只修正 `20-imitation/`、`21-enterprise-wrappers/` 或 `22-review-and-practice/`。

正確判斷方式：

```text
錯誤來源在正式筆記
  → 候選：先修正式筆記
  → 候選：完成 notes content review
  → 候選：再檢查或同步受影響下游
```

如果下游材料需要加入正式筆記沒有教過的新觀念：

```text
候選：先確認正式筆記是否已包含該觀念
  → 若正式筆記沒有，候選：先補正式筆記
  → 候選：完成 notes content review
  → 候選：再更新下游
```

## 資產與引用規則

資產異動不能只判斷檔名，必須檢查所有可能引用該資產的地方。

候選檢查範圍：

```text
<章節>/origin/ 引用
<章節>/atomic/ 引用
<章節>/*.md 正式筆記引用
20-imitation/ 引用
21-enterprise-wrappers/ 引用
22-review-and-practice/ 中的圖片、附件或來源連結
README 或其他索引文件中的連結
```

若資產改名、搬移或刪除後仍有舊引用，會造成圖片、附件、索引或練習來源失效。若後續需要實際改檔，應由對應的執行型流程處理。

## progress-tracker.md 建議標記

`00-roadmap/progress-tracker.md` 是目前 repo 的進度追蹤文件。更新判斷時只提出建議標記，不直接修改狀態表。

建議標記原則：

- 只針對受影響章節或目錄提出建議。
- 不修改 `progress-tracker.md` 的欄位結構。
- 不確定下游是否已過期時，建議標記為 `待複習` 或在備註中寫明需要檢查。
- 若某層已由外部流程重生成並完成檢查，才建議標記為 `已完成`。
- 若某層只在需要時補充，且本次未要求產出，建議標記為 `按需補充`。
- 需要檢查或補做的事項，建議寫入「備註」或後續任務說明。

現有狀態值：

```text
未開始
閱讀中
已整理
待複習
已完成
按需補充
```

維護概念對應：

| 維護概念 | `progress-tracker.md` 對應方式 |
| --- | --- |
| 來源與版本基準 | `01-origin/` 總進度列 |
| 章節 origin 整理 | 對應章節目錄或元件進度列的狀態與備註 |
| atomic 切分與審查 | 對應章節目錄或元件進度列的產出物與備註 |
| 正式筆記生成 | 對應章節目錄或元件進度列的筆記與產出物 |
| notes content review | 對應章節目錄或元件進度列的狀態、備註與待複習標記 |
| 仿寫練習 | `20-imitation/` 總進度列 |
| 企業封裝練習 | `21-enterprise-wrappers/` 總進度列 |
| 複習與練習材料 | `22-review-and-practice/` 總進度列 |

## 判斷型輸出格式

當使用者要求判斷某次改動的影響範圍時，預設使用以下格式：

```text
## 1. 改動摘要

## 2. 最新正確來源

## 3. 改動類型

## 4. 影響範圍判斷

## 5. 需要檢查的內容

## 6. 候選重生成 / 候選同步範圍

## 7. progress-tracker.md 建議標記

## 8. 過期內容風險

## 9. 建議下一步
```

判斷型任務固定：

```text
不改檔
不重生成
不同步 progress-tracker.md
只提出影響範圍、候選處理範圍與建議標記
```

## 章節完成判斷

一個章節可建議視為完成，至少符合：

```text
來源已整理，且可追溯到 01-origin/ 或章節 origin
資產已標準化，或確認無本地資產
atomic 已產生並完成內容審查
正式筆記已產生
notes content review 已完成
下游材料已根據正式筆記建立，或確認不需要並有備註
progress-tracker.md 已由外部執行流程完成同步
```

若 `20-imitation/`、`21-enterprise-wrappers/` 或 `22-review-and-practice/` 中任一層不需要產出，應在備註或後續任務中說明原因。
