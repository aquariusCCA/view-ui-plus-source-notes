# 階段目標

本文件用來定義每個學習階段的目標、輸出物與檢查點。每完成一個階段，都應該回來檢查是否真的能說清楚，而不是只完成檔案數量。

## 階段 1：專案地圖

目標：

- 確認源碼版本。
- 理解 View UI Plus 的整體目錄與模組分層。
- 建立後續筆記的分類邊界。

輸出物：

- 來源紀錄
- 專案目錄導覽
- 架構總覽筆記

檢查點：

- 能說明 `01-origin/` 到 `22-review-and-practice/` 各目錄的責任。
- 能指出元件、樣式、工具函數、型別與建置設定的大致位置。

## 階段 2：入口、插件與公共 API

目標：

- 理解元件庫如何被 Vue app 安裝。
- 理解元件如何被全域註冊與按需使用。
- 理解公開 API 與型別系統如何協作。

輸出物：

- plugin system 筆記
- public API 筆記
- 型別導出整理

檢查點：

- 能從 `app.use` 追到元件註冊。
- 能從一個元件用法追到 Props、Emits、Slots 與實作檔案。

## 階段 3：低複雜度元件

目標：

- 建立固定元件閱讀方法。
- 熟悉元件命名、Props、class、slot、event 與樣式之間的關係。
- 累積基礎元件分析樣本。

輸出物：

- Button / Icon / Divider 等元件分析
- 元件分析模板
- 基礎元件 API 表

檢查點：

- 能獨立拆解一個簡單元件。
- 能說明元件 API 設計是否清楚、哪些地方可擴展。

## 階段 4：複合元件

目標：

- 理解父子元件協作。
- 理解狀態共享、上下文傳遞與複雜互動。
- 掌握表單、導航、資料展示與浮層元件的共同模式。

輸出物：

- Form / Select / Table / Tree / Modal 等元件分析
- 元件資料流圖
- 複合元件設計模式整理

檢查點：

- 能畫出一個複合元件的元件樹與主要資料流。
- 能指出狀態來源、事件出口、slot 擴展點與樣式狀態。

## 階段 5：工程化與可維護性

目標：

- 理解樣式系統、測試策略、建置流程與發布流程。
- 知道元件庫如何維持一致性與可回歸性。

輸出物：

- style system 筆記
- testing 筆記
- build release 筆記

檢查點：

- 能追蹤一個元件從源碼到打包產物的路徑。
- 能說明一個行為應該如何補測試。

## 階段 6：仿寫、封裝與複習

目標：

- 將閱讀結果轉成可實作能力。
- 基於 View UI Plus 設計企業後台二次封裝。
- 透過題目、卡片與重構練習固定知識。

輸出物：

- 仿寫元件
- 企業封裝案例
- 測驗題、卡片、面試題、重構練習

檢查點：

- 能不看原始碼仿寫一個簡化元件。
- 能設計 SearchForm、CrudTable、BusinessModal 這類業務元件的 Props、Slots 與事件。
