# 生成主題筆記工作流程

這份提示詞用於依指定主題與來源範圍，生成 `02-notes/` 下的書本型、教學型、詳細筆記。

## 使用者需提供

請在提問中提供以下資訊：

| 欄位 | 說明 |
| --- | --- |
| 主題名稱 | 例如 `Button 元件`、`Vue plugin install flow`、`Message 命令式 API` |
| 目標輸出路徑 | 例如 `02-notes/07-components/button/01-button-overview.md` |
| 來源檔案範圍 | 需要閱讀與整理的原始碼、型別、樣式、測試或文件路徑 |
| 筆記深度 | 預設為書本型、教學型、詳細 |
| 閱讀邊界 | 哪些內容不在本次筆記展開 |

## 工作流程

### 1. 確認範圍

先確認主題、輸出路徑與來源檔案是否一致。如果來源範圍明顯缺少重要檔案，先列出缺少的檔案類型，例如 component 實作、index export、style、type declaration、test 或 example。

### 2. 建立來源地圖

閱讀來源後，先整理一張 source map：

- 主入口檔案。
- 核心實作檔案。
- 支撐檔案。
- 對外型別或 public API 檔案。
- 樣式檔案。
- 測試或範例檔案。

這張地圖用來決定筆記的敘事順序。

### 3. 抽出核心問題

在正式寫筆記前，先抓出這個主題要回答的 3 到 6 個核心問題。例如：

- 這個元件解決什麼 UI 問題？
- 它的 props 如何影響 class、狀態與渲染？
- 它如何對外發出事件？
- 它如何和樣式系統、型別宣告、測試案例相互對應？

### 4. 寫成書本型筆記

依 `formats/book-style-note.md` 的格式產出完整筆記。筆記應該有清楚的章節遞進：

1. 先講用途與位置。
2. 再講整體結構。
3. 接著拆解 public API。
4. 然後進入內部實作。
5. 最後整理設計模式、注意事項與後續分流。

### 5. 自我檢查

輸出前檢查：

- 是否每個重要結論都能回到來源檔案。
- 是否避免憑空增加不存在的 API。
- 是否有說清楚資料流、事件流、樣式流或型別對應。
- 是否符合 `02-notes/` 作為主幹知識的定位。
- 是否沒有把練習題、複習卡或 demo 混入主筆記。

## 回覆方式

若可以直接寫檔，請將筆記寫入指定路徑。若只能輸出文字，請先給出目標檔名，再輸出完整 Markdown 內容。
